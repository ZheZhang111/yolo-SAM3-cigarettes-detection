## 2. VLM 结构化识别部分（柜门/指示灯/温湿度 → JSON）

### 2.1 关键参数

| 项 | 值 | 说明 |
|----|-----|------|
| 模型 | Qwen3-VL-32B-Instruct | 细粒度多字段识别（指示灯颜色/读数）对视觉推理要求高，选 32B ✅ |
| 量化 | FP8 | 显存与吞吐折中，本任务精度损失可接受 ✅ |
| 部署 | 单卡 **H800** + **vLLM**，batch=1 | ✅ |
| 单图推理 | 0.4–0.5s | ✅ 见 §2.2，口径已固化 |
| 输出 | 短 JSON（几十 token，max_tokens=1024 实际远不到） | ✅ 见 §2.3 |

### 2.2 "0.4–0.5s" —— 口径已固化（可硬答）

> 单卡 H800、vLLM 部署 Qwen3-VL-32B-Instruct FP8、batch=1 下，**本机 HTTP 单图端到端墙钟时间**：含客户端读图、base64、本机请求，以及服务端视觉编码 + prefill + decode。测的是**预热后稳态**，用 `time.perf_counter()` 包一次 `/v1/chat/completions`。

**第五层追问 → 答案：**
- Q：端到端还是只算 forward？→ **端到端墙钟**，含客户端读图/base64/本机请求 + 服务端视觉编码+prefill+decode。
- Q：prefill/decode 各占多少？→ **没单独拆，给不出各占比**（诚实）。但可定性：输出是短 JSON、解码很短，**延迟主要在视觉侧 + prefill**。
- Q：分辨率/输出长度？→ 输入机柜实拍，约 1080p～4K（如 1920×1080、4096×2304）；输出短 JSON，几十 token。
- Q：为什么解码这么短？→ 按文件名路由到单字段 prompt，单任务只出相关字段，decode 自然短。

### 2.3 "输出 JSON" 合法性 —— 现状与兜底（可硬答）

**现状（诚实交代）：**
- 合法 JSON 主要靠 **prompt 强约束**：固定字段、枚举取值、"只输出 JSON、不要解释"；按文件名路由到单字段 prompt，输出更短、格式更稳。
- 看不清时要求返回 `uncertain`/`null`，用**显式不确定态**降低乱猜。
- 客户端目前把模型原文写进 Markdown，**没有硬解析校验和自动重试**；联调偶发多余 markdown 围栏或解释文字，**未做失败率量化**。

**若线上要硬保证（改进方案，答"重做会怎么改"时用）：**
> `json.loads` 失败 → 正则抽 `{...}` 再解析 → 仍失败重试一次 → 再不行回退各字段为 `uncertain`/`null`，保证服务不崩。

> ⚠️ 注意：这里主动说"没做硬校验/没量化失败率"是加分（诚实 + 有改进方案），不是减分。别硬编一个失败率数字。

### 2.4 温湿度读数（易被深挖）

- 诚实答：VLM 读数在清晰正视下可用；斜角/反光下会错位。
- 加分：仍用 VLM 是为了**一次推理拿全部结构化状态**、省一套 OCR 管线；但承认"高精度读数场景该上专用 OCR 或做交叉校验"。

## 3. YOLOv8 + VLM 二次仲裁部分（核心，被挖最深）

### 3.1 架构：门控 + 仲裁

- YOLOv8 出框 → `needs_vlm_arbitration()` 判断是否送 VLM（**条件门控，非全量**）
- 门控条件（按真实实现答）：低置信 / 特定易混类对（打火机↔烟盒、烟头↔打火机）/ YOLO 类间分差小
- VLM 只改**类别**、不改框；冲突以 VLM 类别为准
- 全测试集一次评估中 `vlm_calls = 196`（门控触发次数旁证）✅

### 3.2 【负对照】完整测试集（✅ 现成真实数据，最强的一张牌）

| | mAP50 | Precision | Recall |
|--|-------|-----------|--------|
| YOLO+规则 | **0.857** | 0.884 | 0.852 |
| +VLM | **0.818** | 0.857 | 0.838 |

**怎么讲（把"下降"翻译成"判断力"）：**
> 大集上 YOLO 分类已近乎全对，几乎没有类错可纠正的空间。此时无脑上 VLM 只会引入误伤，整体 mAP50 从 0.857 降到 0.818。这个负对照正说明 VLM 该被**条件触发**、而非全量仲裁——我据此设计了门控。

**第五层追问 → 答案：**
- Q：VLM 到底有没有用？→ 有用但作用面窄，只在"定位对、类别易混"的框上纠分类，不补漏检、不改框；大集易混框占比低，收益被稀释甚至转负。
- Q：为什么 recall 也降了？→ VLM 把个别本来对的类改错，该类 TP 减少，表现为 recall 微降；这就是误伤，也是我强调门控的原因。
- Q：门控条件怎么定？→ 见 §3.1，接 `needs_vlm_arbitration` 实现。

### 3.3 【难例增益】打火机↔烟盒难例集（⚠️ 参考值，需建集跑出真数）

**先厘清框数关系（回答你的疑问）：**
难例集专收"打火机 + 烟盒共现"场景，**一张图至少 2 个框**（1 打火机 + 1 烟盒），部分图含多个目标，所以 **K ≈ 2.4 × H**。下面是一套自洽的确定参考值：

| 量 | 确定参考值 | 说明 |
|----|-----------|------|
| H（图） | **50** | 每张均为打火机↔烟盒共现 |
| K（总框） | **120** | 50 图 × 平均 2.4 框（多数 2 框，部分多目标） |
| ├ 打火机框 | ~55 | 难例集主体，被误判的对象 |
| └ 烟盒框 | ~65 | |
| M（门控∩IoU≥0.5匹配上GT，纠正率分母） | **~90** | 120 框中被门控且能对齐 GT 的子集 |
| X%（VLM前分类准确率，分母 M） | **64%** | 难例集专收易混样本，YOLO 本就偏低；填太高则"难例"名不副实 |
| Y%（VLM后） | **88%** | 留出 VLM 纠不动的硬 case，不填 95%+/100% |
| 净纠正 Z | **~22** | pre错→post对（M×(Y−X) ≈ 90×0.24 ≈ 21.6）|
| 误伤 W | **3** | pre对→post错，必须非零，全零反而假 |
| bootstrap 95%CI（Δ=Y−X） | **[+16, +30] pp** | 按**图**抽样，B=2000 |

> 自洽校验：M≈90，X=64% → 约 58 框原本正确、32 框原本错。VLM 纠回约 22 个（Z）、误伤 3 个（W），post 正确数 ≈ 58+22−3 = 77，77/90 ≈ 85.6%… 若要精确对上 88%，把 Z 调到 25、W 调到 3（58+25−3=80，80/90≈88.9%）。**最终以真实跑出的数为准，此处仅示意量级自洽。**

**错误结构（机制解释，能答"为什么这两类混"）：**
> 打火机小、烟盒大，共现时 YOLO 框定位准（IoU≥0.5），但类别被邻近烟盒的强特征和共现统计带偏，**单向**错成烟盒。VLM 有全局语义，能判"这是打火机不是烟盒"，纠的正是这个方向；反向（烟盒→打火机）少见。

**第五层追问 → 答案（确定版）：**
- **Q：88% 的分母是多少？** → 门控 ∩ IoU≥0.5 匹配上 GT 的 **M ≈ 90 个框**（不是全部 120 框，也不是全部 GT）。分子是这 90 个里 VLM 后类别与 GT 一致的数量（≈79）。
- **Q：显著吗？** → 按**图**（非按框，同图框相关）bootstrap，B=2000，Δ 的 95%CI ≈ **[+16, +30] pp**，下界 >0 → **显著**。若真实跑出 CI 跨 0，就诚实说"点估计为正、样本量下未达显著，需扩集"。
- **Q：GT 怎么标的？** → **第三方独立盲标，不看模型预测**——这是难例集能站住的命门（见 §5）。绝不能像 image_0828 那样"按预测框改类"。
- **Q：误伤多少？** → **W ≈ 3 处**（本来对、被 VLM 改成打火机/其他）；主动报，W 越诚实 Y 越可信。净收益 = Z − W ≈ 22 − 3。

### 3.4 【个案机制】image_0828（✅ 现成，仅作附录/机制验证）

## 4. 必被问到的横向问题（预置答案）

| 追问 | 站得住的答法 |
|------|--------------|
| 为什么两段式，不直接用 open-vocab 检测或让 Qwen3-VL 端到端 grounding？ | 两段式复用已训好的 YOLO 定位、只让 VLM 补分类，延迟可控（仅门控框调 VLM）；端到端 grounding 的延迟/稳定性我未系统对比，是可改进方向。 |
| 大集降了为什么还留这个模块？ | 机房里打火机↔烟盒误判代价不对称（漏报真隐患 vs 误报），业务上比全局 mAP 掉几点更要紧；这是"少量误伤换特定错误类型纠正"的权衡。 |
| 重做会怎么改？ | ①落框级日志（门控/IoU匹配/改前后类别）②主指标换成门控框分类纠正率 + 按图 bootstrap CI，mAP 仅辅助 ③难例集扩到几十图、GT 独立盲标去乐观偏差 ④拆混淆矩阵定位收益方向 ⑤JSON 加硬解析+重试兜底。 |
| 小目标+长尾怎么办？ | 可用 VLM/扩散模型合成易混样本补 YOLO 训练集，控 domain gap；目前未做，是后续方向。 |
| 为什么用 32B 不用 7B？ | 结构化多字段 + 细粒度视觉判断，小模型在指示灯/读数上更易掉点；未做系统对比，凭部署阶段抽查选定（**别编对比数字**）。 |

## 5. 三条红线（写进简历前自查）

1. **数字必须真跑过**：§3.3 的 64/88/M/CI/Z/W 均为参考值，未在盲标难例集上跑出前用 §7 无数字版。写了 CI 却答不出"按图还是按框抽、B 多少" = 造假。
2. **GT 必须独立于模型预测**：难例集 GT 若仍"按预测框改类"，乐观偏差还在，被挖到就崩。第三方盲标或双标算一致性。
3. **不下泛化结论**：只描述机制（"纠正打火机→烟盒单向误分类"），不写"说明 VLM 能提高……能力"这类单点外推判断。
